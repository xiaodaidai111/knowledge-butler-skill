# 一休：AI 原生项目协作与团队共享记忆系统技术方案

## 文档说明

本文档依据“AI+软件创新”赛题技术方案参考大纲编写，围绕一休系统的产品定位、技术架构、核心功能、开发测试、部署方案、应用价值与未来规划进行系统说明。项目面向人工智能软件研发过程中的团队协作、上下文管理、知识沉淀与智能体接入问题，构建一个支持外部 AI 工作台同步、团队共享记忆、上下文引擎、项目管理和评测闭环的 AI 赋能软件系统。

## 一、产品概述与定位

### 1. 背景与目标

随着大模型和 AI 编程工具的快速发展，软件研发方式正在从传统的人力驱动逐步转向“人 + AI 智能体”协同模式。Codex、Claude、ChatGPT、Cursor 等工具已经能够参与需求分析、代码生成、错误定位、文档编写、测试设计和项目复盘等环节，但在实际团队使用过程中仍存在明显痛点。

第一，AI 对话和任务过程难以沉淀。开发者在不同 AI 工具中完成了大量分析、推理和修改，但这些过程通常停留在单次会话中，任务结束后难以被团队检索和复用。

第二，项目上下文容易丢失。软件研发涉及需求文档、代码文件、接口设计、历史 Bug、PR 记录、测试结果和团队决策等多源信息。AI 在执行任务时往往只能看到局部上下文，容易重复分析、遗漏约束或产生不符合项目实际的建议。

第三，团队经验难以资产化。很多问题在不同项目或不同成员之间反复出现，但根因、尝试过程、最终方案和适用边界没有被结构化保存，导致团队持续重复劳动。

第四，AI 生成结论缺少审核机制。AI 可以快速总结经验，但其中可能包含错误判断、临时方案、敏感信息或不适用于当前项目的建议，如果直接进入知识库，会降低团队知识资产的可信度。

一休系统的研发目标是构建一个面向 AI 原生项目协作的智能软件系统，将外部 AI 工具产生的任务记录、代码变更、关键决策、风险提示和验证结果自动导入一休，通过上下文引擎进行结构化解析，再经过人工审核沉淀为团队 Memory、Skill 和 Eval 资产，形成“任务执行、经验提取、审核入库、上下文复用、评测验证”的闭环。

该系统旨在推动人工智能从单点辅助工具升级为可沉淀、可追踪、可复用、可评测的团队协作基础设施，为人工智能软件产品研发提供一种新的工程化落地方式。

### 2. 产品定位

一休定位为 AI 赋能软件系统与智能项目协作平台，属于“AI 原生团队记忆与上下文管理系统”。它不是单纯的项目管理软件，也不是普通 AI 聊天工具，而是连接 AI 工作台、项目协作过程、团队知识库和评测系统的智能中枢。

产品类型包括：

1. AI 赋能软件系统：通过 AI 解析、结构化抽取和候选资产生成能力，提高项目协作和知识沉淀效率。
2. 智能应用系统：面向软件研发团队提供上下文引擎、项目管理、团队记忆、审核入库和智能体辅助操作。
3. Agent 协作基础设施：为 Codex、Claude、ChatGPT、Cursor 等外部智能体提供固定格式上传和 MCP 接入能力。

目标用户包括：

1. 软件开发团队：用于沉淀项目经验、减少重复问题、提升研发协作效率。
2. AI 应用研发团队：用于管理大模型任务过程、Agent 执行记录、提示词经验和评测用例。
3. 学生竞赛团队：用于统一管理项目进展、技术方案、实验记录和团队知识。
4. 技术负责人和项目管理者：用于掌握项目状态、风险、决策依据和团队能力积累。
5. 企业知识管理人员：用于把项目实践经验转化为可检索、可审核、可复用的知识资产。

核心应用场景包括：

1. AI 编程任务结束后自动同步任务总结。
2. 从外部 AI 对话中提取项目进展、关键决策、风险和待办。
3. 将重复 Bug 和失败任务转化为团队 Memory。
4. 将可复用流程沉淀为 Skill。
5. 将验证经验转化为 Eval 回归用例。
6. 为新任务自动生成 Context Pack，减少上下文准备成本。

系统差异化优势主要体现在：

1. 上下文组装能力：能够围绕任务自动关联项目、文档、代码、历史经验和相关 Skill。
2. 结构化抽取能力：通过固定上传协议与解析器，将 AI 工作过程转化为标准字段和候选资产。
3. 审核可信机制：AI 自动生成的内容不会直接进入团队记忆，而是先进入候选区，由人工审核后入库。
4. 资产闭环能力：任务记录可以演化为 Memory、Skill 和 Eval，不再停留在一次性对话中。
5. 多工具接入能力：支持 Codex、Claude、ChatGPT、Cursor 等外部 AI 工具通过 MCP/API 接入。

## 二、技术架构与创新

### 1. 整体架构

一休系统采用前后端分离的 Web 架构，由 Vue3 前端工作台、Flask 后端服务、SQLite 数据库、MCP/API 接入层和 AI 解析引擎组成。

系统总体架构可分为六层：

第一层为用户交互层。该层由 Web 前端工作台实现，提供首页、项目管理、上下文引擎、团队记忆、外部 AI 导入、MCP 配置、审核管理和个人中心等页面。用户可以在页面中查看项目状态、导入外部 AI 内容、审核候选资产、查看团队记忆和管理项目进展。

第二层为业务 API 层。该层由 Flask 后端路由提供统一接口，包括项目数据接口、知识库接口、外部 AI 导入接口、MCP JSON-RPC 接口、候选资产审核接口和上下文包生成接口。

第三层为 AI 接入层。该层通过 MCP 风格 JSON-RPC 接口对外暴露工具，使 Codex 等外部智能体可以调用 `yixiu.import_external_ai` 工具，将任务目标、工作总结、改动文件、关键决策、风险、待办、验证结果和候选资产上传到一休。

第四层为智能解析层。该层负责对外部 AI 上传内容进行结构化解析。目前系统支持固定格式解析器 `codex_fixed_v1`，能够优先识别固定字段，也支持普通文本导入的规则化解析。

第五层为数据持久化层。系统使用 SQLite 存储项目、知识、外部导入记录、候选资产、审核状态和团队记忆。后续可以迁移到 MySQL 或 PostgreSQL 支撑多人协同和生产部署。

第六层为知识资产层。该层包含 Team Memory、Skill Candidate、Eval Case 和项目进展记录。所有 AI 自动生成的资产默认进入待审核状态，审核通过后才能成为团队共享记忆或可复用技能。

主要数据流如下：

1. Codex 或 Claude 完成任务后，按照固定格式调用一休 MCP 工具上传任务记录。
2. 后端 MCP 接口接收 JSON-RPC 请求，调用外部 AI 导入服务。
3. 解析器识别固定字段，生成项目进展、关键决策、风险、待办、Memory 候选、Skill 候选和 Eval 候选。
4. 候选资产写入数据库，状态为待审核。
5. 用户在前端审核页面查看候选资产，选择通过或退回。
6. 审核通过的 Memory 写入团队记忆库，供后续上下文引擎检索和复用。
7. 新任务启动时，上下文引擎根据项目、问题类型、历史经验和相关 Skill 自动生成 Context Pack。

### 2. 技术选型

前端技术选型为 Vue3 + Vite。Vue3 适合构建交互复杂的 Web 工作台，能够通过响应式状态管理实现项目列表、候选资产审核、导入记录和配置模板的动态展示。Vite 提供快速构建和开发服务，适合竞赛项目快速迭代和演示部署。

后端技术选型为 Flask。Flask 轻量、灵活，适合快速构建统一 API 服务、接入 JSON-RPC 接口和组织业务路由。项目后端通过 Flask Blueprint 管理一休相关接口，便于扩展项目管理、团队记忆、AIOS、外部导入等模块。

数据库选型为 SQLite。SQLite 适合本地演示、竞赛答辩和轻量部署，不依赖复杂数据库环境，便于评审快速运行。系统设计上保留迁移空间，后续可以替换为 MySQL 或 PostgreSQL，以支撑多用户、多团队和高并发场景。

AI 接入技术选型为 MCP/API。MCP 适合将一休暴露为智能体可调用工具，使外部 AI 能主动把任务成果上传到系统。API 接口适合前端页面和其他平台集成。

数据格式选型为固定 JSON 上传协议。系统设计了 `yixiu.codex.upload.v1` 固定格式，用于规范 Codex 等外部 AI 上传内容。相比自由文本总结，固定格式可以提升解析稳定性、减少字段遗漏，并便于后续评测和审计。

审核机制采用 pending review 状态流转。AI 自动生成内容先进入候选状态，人工通过后才能进入团队记忆，避免错误经验污染知识库。

### 3. 创新应用

一休的核心创新在于将 AI 工作过程从“即时对话”转化为“可计算、可审核、可复用的团队资产”。

第一，提出 AI 工作台内容资产化机制。传统 AI 编程工具通常只关注当前任务完成，而一休关注任务完成后的经验沉淀。系统能够从 Codex、Claude 等工具中获取任务目标、代码变更、关键决策、风险和验证结果，并转化为项目资产。

第二，提出固定格式上传协议。通过 `yixiu.codex.upload.v1`，系统要求外部 AI 按标准字段上传，解决自由文本总结难解析、质量不稳定和字段缺失的问题。

第三，提出团队记忆审核机制。AI 生成内容不直接进入知识库，而是进入候选区，经过人工审核后再入库。这一机制兼顾 AI 自动化效率和团队知识可信度。

第四，提出 Memory、Skill、Eval 三类资产闭环。Memory 用于保存团队经验，Skill 用于保存可复用流程，Eval 用于验证能力是否可靠。三者共同构成团队能力增长体系。

第五，提出上下文引擎。系统不是被动保存文档，而是能够在新任务开始时自动组装相关需求、代码、文档、历史经验、风险和 Skill，帮助 AI 和团队成员快速进入任务状态。

与同类产品相比，一休的差异在于：普通项目管理工具重在任务流转，普通知识库重在文档保存，普通 AI 聊天工具重在即时问答，而一休重在 AI 协作过程的结构化沉淀、审核和复用。

## 三、功能设计与实现

### 1. 核心功能

#### 1.1 项目管理中心

项目管理中心用于替代传统任务管理模块，记录项目目标、当前进展、负责人、参与成员、阶段状态、里程碑、风险、交付物和历史进展。它不仅记录“任务是否完成”，还记录“项目如何推进、遇到什么问题、做出什么决策、后续如何复用”。

AI 实现方式：系统从外部 AI 上传内容中提取 `task_goal`、`work_summary`、`todos` 和 `validation` 字段，自动生成项目进展候选。用户审核后可将其作为项目时间线的一部分。

#### 1.2 Context Engine 上下文引擎

上下文引擎用于为任务自动组装 Context Pack。它会根据项目名称、任务描述、历史导入记录和团队记忆，组织与当前任务相关的需求、代码、文档、历史问题、关键决策、风险边界和推荐 Skill。

AI 实现方式：系统通过结构化检索和规则化匹配，从 Memory、Skill、Eval 和项目记录中召回相关内容，形成任务上下文包。后续可引入向量检索和大模型重排序，提高召回准确率。

#### 1.3 外部 AI 导入

外部 AI 导入模块用于接收 Codex、Claude、ChatGPT、Cursor 等工具产生的任务总结、对话摘要、代码变更和 PR 说明。用户可以手动粘贴，也可以由智能体通过 MCP 自动上传。

AI 实现方式：系统支持两种解析方式。第一种是固定格式解析，识别 `task_goal`、`work_summary`、`changed_files`、`decisions`、`risks`、`todos`、`validation` 等字段。第二种是自由文本规则解析，根据关键词提取决策、风险、待办和文件线索。

#### 1.4 MCP 自动上传

系统通过 `/api/yixiu/mcp` 提供 MCP 风格 JSON-RPC 接口，支持 `initialize`、`tools/list` 和 `tools/call` 方法。外部智能体可以调用 `yixiu.import_external_ai` 工具上传固定格式任务记录。

固定上传字段包括：

1. `task_goal`：任务目标。
2. `work_summary`：完成内容。
3. `changed_files`：改动文件。
4. `decisions`：关键决策。
5. `risks`：风险与边界。
6. `todos`：待办事项。
7. `validation`：验证结果。
8. `memory_candidates`：团队记忆候选。
9. `skill_candidates`：Skill 候选。
10. `eval_cases`：Eval 候选。
11. `next_actions`：下一步建议。

#### 1.5 Team Memory 团队记忆库

团队记忆库存储经过审核的团队经验，包括问题背景、尝试过程、根因、解决方案、适用条件、风险边界和验证记录。它区别于普通文档库，因为其中的内容经过结构化处理和人工审核，能够被上下文引擎调用。

AI 实现方式：外部 AI 上传内容会生成 Memory 候选，候选内容经过人工审核后写入团队记忆表，供后续检索和复用。

#### 1.6 Memory Evolution 记忆演化引擎

记忆演化引擎从任务记录、Bug、PR、聊天和验证结果中提炼可复用经验。其目标是将项目过程中的临时信息转化为长期可用的团队资产。

AI 实现方式：系统通过解析器生成 `memory_candidate`、`skill_candidate` 和 `eval_case` 三类候选资产，并为每项资产附加置信度和审核状态。

#### 1.7 Eval Lab 评测中心

Eval Lab 用于保存和验证 Skill 是否有效。每个从任务中提取出的可复用流程都可以配套生成 Eval 用例，用于后续回归测试和质量比较。

AI 实现方式：系统从 `validation` 和 `eval_cases` 字段中生成评测候选，记录检查项、预期结果和可复用场景。

#### 1.8 Agent / Router 操作面板

Agent / Router 操作面板用于展示推荐上下文、推荐 Skill、推荐 Agent 和执行链路。它不是简单聊天框，而是工作流智能辅助层，帮助用户理解 AI 的操作路径和依据。

### 2. 辅助功能

#### 2.1 用户与个人中心

个人中心用于展示用户参与项目、导入记录、审核记录、知识贡献和个人资产。它帮助团队了解每个成员在项目推进和知识沉淀中的贡献。

#### 2.2 数据统计与看板

系统提供导入记录数量、候选资产数量、待审核数量、已通过数量等统计指标。后续可扩展为团队能力增长看板，展示 Skill 覆盖率、重复问题减少率、AI 导入效率和知识复用次数。

#### 2.3 审核管理

审核管理是保障系统可信度的关键模块。所有由 AI 自动生成的 Memory、Skill、Eval 候选都需要人工审核。审核结果包括通过、退回和待审核。通过后的 Memory 可写入团队记忆库，退回内容保留为导入记录但不参与推荐。

#### 2.4 MCP 配置页

MCP 配置页展示一休接入地址、鉴权方式、推荐给 Codex 或 Claude 的提示词以及固定上传 JSON 模板。用户可以将模板配置到外部 AI 工具中，使其在任务结束时自动上传结果。

### 3. 扩展性设计

系统在架构上预留了多方向扩展能力。

第一，模型升级接口。当前系统使用规则化解析和固定格式解析，后续可接入真实大模型进行更高质量的信息抽取、语义分类和候选资产生成。

第二，多 AI 工具接入。系统已支持 Codex 固定格式上传，后续可扩展 Claude、ChatGPT、Cursor、GitHub Copilot、飞书、GitHub PR 和 Issue Webhook。

第三，数据库扩展。SQLite 可用于本地演示，后续可迁移到 MySQL 或 PostgreSQL，并增加多租户、权限、审计和备份机制。

第四，检索能力扩展。上下文引擎可从关键词检索升级为向量检索、知识图谱检索和大模型重排序。

第五，评测能力扩展。Eval Lab 可支持自动执行测试、比较不同 Skill 版本的成功率、成本和执行质量。

第六，权限能力扩展。生产环境可增加 OAuth、API Token、工作区权限、项目权限、审核角色和敏感字段脱敏。

## 四、开发测试与部署

### 1. 开发流程

一休项目采用迭代式开发流程，从原有工程逐步改造为 AI 原生项目协作系统。

第一阶段为需求分析与产品重构。该阶段确定系统从传统设备检修/任务管理思路转向 AI 原生团队记忆与项目协作系统，明确核心模块包括上下文引擎、项目管理、团队记忆、记忆演化、评测中心和外部 AI 导入。

第二阶段为前端 Web 工作台改造。该阶段移除无关的 uni-app 与旧业务入口，保留可运行 Web 系统，重构左侧导航、首页、项目管理、上下文引擎、团队记忆和个人中心页面。

第三阶段为后端接口建设。该阶段基于 Flask 统一后端新增外部 AI 导入、MCP 配置、候选资产审核、团队记忆写入等接口。

第四阶段为数据表设计与落库。该阶段新增外部 AI 来源表、导入记录表和候选资产表，用于保存外部工具上传内容及其解析结果。

第五阶段为 MCP 自动上传能力建设。该阶段实现 `/api/yixiu/mcp` JSON-RPC 接口，支持智能体调用 `yixiu.import_external_ai` 工具。

第六阶段为固定格式协议建设。该阶段设计 `yixiu.codex.upload.v1` 固定字段，使 Codex 可以以标准格式上传任务结果。

第七阶段为验证和优化。该阶段通过后端语法检查、前端构建、接口调用和本地服务联调验证系统可运行性。

团队分工可划分为：

1. 产品设计：负责需求分析、模块定义、用户流程和参赛材料。

6. 测试与部署：负责构建测试、接口测试、运行环境说明和演示视频准备。

### 2. 代码实现

关键 AI 功能集中在外部 AI 导入和 MCP 工具调用链路中。

核心接口包括：

1. `GET /api/yixiu/integrations/mcp/manifest`：获取 MCP 接入配置、工具说明和上传模板。
2. `POST /api/yixiu/mcp`：接收 MCP JSON-RPC 请求。
3. `POST /api/yixiu/integrations/imports`：创建外部 AI 导入记录。
4. `POST /api/yixiu/integrations/imports/<import_id>/parse`：重新解析导入内容。
5. `PUT /api/yixiu/integrations/artifacts/<artifact_id>/review`：审核候选资产。

关键解析流程如下：

1. 后端接收 Codex 上传的 JSON 参数。
2. 判断是否包含固定字段或 `codex_report`。
3. 将固定字段统一转换为标准导入内容。
4. 调用解析函数生成结构化结果。
5. 写入外部导入记录表。
6. 生成候选资产，包括项目进展、关键决策、风险提醒、待办事项、Memory 候选、Skill 候选和 Eval 用例。
7. 返回结构化结果给调用方。

固定格式示例如下：

```json
{
  "provider": "codex",
  "project_name": "一休 Web 端",
  "title": "Codex 任务总结",
  "content_type": "summary",
  "task_goal": "本次任务要解决的问题",
  "work_summary": ["完成的关键改动"],
  "changed_files": ["frontend/App.vue", "server/backend/routes/yixiu.py"],
  "decisions": ["关键技术或产品决策"],
  "risks": ["尚未验证或需要人工确认的风险"],
  "todos": ["后续事项"],
  "validation": ["运行过的测试或验证结果"],
  "memory_candidates": ["可沉淀到团队记忆的经验"],
  "skill_candidates": ["可演化为 Skill 的流程"],
  "eval_cases": ["可用于回归评测的检查项"],
  "next_actions": ["建议下一步动作"]
}
```

该实现体现了规范性和优化策略：固定字段降低解析不确定性，候选资产状态保证审核安全，统一导入函数避免 REST 与 MCP 两套逻辑重复。

生产环境应启用以下安全策略：

1. 为 MCP/API 接口增加 Token 或 OAuth 鉴权。

3. 增加项目权限和团队空间隔离。
4. 增加审核日志，记录审核人、审核时间和修改意见。
5. 使用 HTTPS 部署，避免上传内容明文传输。

## 五、应用价值与展望

### 1. 应用场景

场景一：AI 编程任务沉淀。

开发者使用 Codex 完成一个功能改造后，Codex 按固定格式上传任务目标、改动文件、关键决策、风险和验证结果。一休自动生成项目进展和 Memory 候选。项目负责人审核通过后，该经验进入团队记忆库。下次团队遇到类似问题时，上下文引擎可以自动召回该经验。

应用价值：减少重复分析时间，提高经验复用率。

场景二：项目进展管理。

团队成员在不同 AI 工具和开发环境中完成任务，一休统一接收外部 AI 上传内容，形成项目进展时间线。管理者可以查看每次任务做了什么、改了哪些文件、还有哪些风险和待办。

应用价值：提高项目透明度，减少口头同步和信息遗漏。

场景三：Bug 复盘与团队记忆。

线上问题修复后，系统从任务记录中提取问题背景、根因、解决方案和验证方式，生成 Memory 候选。审核通过后，该问题成为团队共享经验。

应用价值：降低重复 Bug 出现概率，提升团队工程能力。

场景四：Skill 沉淀。

当团队多次执行类似流程，例如“接口改造后补充前后端联调验证”或“AI 导入内容必须先审核再入库”，系统可以将流程沉淀为 Skill 候选。

应用价值：把个人经验转化为团队标准流程。

场景五：Eval 回归评测。

每次任务的验证结果可以转化为 Eval 用例，后续用于检查 Skill 是否仍然有效。例如系统要求上传固定格式后，Eval 可以检查 parser 是否为 `codex_fixed_v1`，候选资产是否完整。

应用价值：提升 AI 协作流程的可靠性和可验证性。

### 2. 市场分析

随着 AI 编程工具普及，软件团队逐渐从“人写代码”转向“人指挥 AI 完成任务”。这一变化带来了新的基础设施需求：团队需要管理 AI 生成的过程、结论、经验和风险，而不仅仅是管理最终代码。

当前市场上已有项目管理工具、知识库工具和 AI 编程工具，但它们大多解决单点问题。项目管理工具关注任务分派和进度，知识库工具关注文档保存，AI 编程工具关注即时生成，缺少一个连接 AI 工作过程与团队知识资产的系统。

一休的市场竞争力体现在：

1. 面向 AI 原生研发流程，切中 AI 编程普及后的新痛点。
2. 支持 MCP/API 接入，能够连接主流 AI 工作台。
3. 具有审核机制，解决 AI 生成内容可信度问题。
4. 形成 Memory、Skill、Eval 闭环，区别于普通知识库。
5. 适合学生团队、创业团队和企业研发团队逐步落地。

潜在市场包括：

1. AI 软件开发团队。
2. 企业研发管理平台。
3. 高校竞赛团队协作平台。
4. AI Agent 工程化工具链。
5. 知识管理和项目复盘系统。

### 3. 成果总结

一休项目已经完成从普通 Web 系统到 AI 原生项目协作系统的核心改造，形成了较完整的软件功能闭环。

已完成成果包括：

1. 构建了一休 Web 工作台。
2. 将任务管理升级为项目管理中心。
3. 建设了上下文引擎入口。
4. 建设了团队记忆库与候选资产审核机制。
5. 建设了外部 AI 工作台导入模块。
6. 实现了 MCP 风格 JSON-RPC 接口。
7. 实现了 Codex 固定格式上传协议。
8. 实现了固定格式解析器 `codex_fixed_v1`。
9. 实现了项目进展、关键决策、风险、待办、Memory、Skill、Eval 七类候选资产生成。

项目的核心技术突破在于：

1. 将外部 AI 工作过程结构化为标准字段。
2. 将 AI 生成内容转化为可审核候选资产。
3. 将团队记忆、Skill 和 Eval 统一纳入项目协作流程。
4. 通过 MCP 让智能体具备主动上传到一休的能力。
5. 建立了 AI 协作过程的可追踪、可审核、可复用机制。

### 4. 未来规划

当前系统仍存在一些不足。

第一，解析算法仍以规则化和固定格式为主，对复杂自然语言内容的深层语义理解能力有限。

第二，数据库当前以 SQLite 为主，适合本地演示，但在多人协同和高并发场景下需要升级。

第三，权限体系仍需完善，包括用户角色、项目权限、审核权限和外部工具授权。

第四，Eval Lab 目前以候选用例生成为主，尚未完全实现自动执行和结果比较。

第五，系统与 GitHub、飞书、企业微信、CI/CD 平台等外部协作工具的自动同步能力仍有扩展空间。

未来研发重点包括：

1. 引入大模型语义抽取，提高 Memory、Skill、Eval 生成质量。
2. 增加向量检索和知识图谱能力，提高上下文引擎召回准确率。
3. 接入 GitHub PR、Issue、Commit 和 CI 测试结果。
4. 完善 Token/OAuth 鉴权和企业级权限管理。
5. 将 SQLite 升级为 MySQL 或 PostgreSQL。
6. 建设 Eval Lab 自动回归评测能力。
7. 增加团队能力增长看板，统计知识复用率、重复问题减少率和 AI 协作效率。
8. 支持云端部署、多团队空间和多人实时协作。
9. 支持更多外部 AI 工具，如 Claude、ChatGPT、Cursor 和 GitHub Copilot。
10. 建设插件化 Skill 市场，使团队经验能够沉淀为可迁移能力。
